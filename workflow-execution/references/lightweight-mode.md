# 轻量模式说明

## 适用场景

仅适用于以下执行任务：

1. 单任务、小范围代码修复
2. 不涉及复杂数据库设计
3. 不涉及明显的阶段切换
4. 需求边界已经明确，且人工审核已完成

若涉及以下任一项，退出轻量模式，回到完整模式：

1. 多任务并发收口
2. 大范围联调
3. 数据迁移或复杂 SQL 变更
4. 发布风险较高，需完整闸门治理

## 轻量模式最小动作

可以简化为：

1. 明确当前任务
2. 更新任务状态
3. 实现代码
4. 执行最小必要验证
5. 回写最小必要证据
6. 是否自动提交/推送，按用户要求决定

## 可以省略的内容

在确认属于轻量模式后，可以不强制补：

1. 全量阶段切换检查
2. 与当前任务无关的额外文档刷新
3. 非关键测试命令
4. 自动推送或发布闸门（仅当用户明确缩小范围）

## 不能省略的内容

以下原则在轻量模式下仍然必须保留：

1. `PRD` 基线不能省
2. 显式开工门不能省
3. 任务状态正确不能省
4. 至少一份可追溯证据不能省
5. 若存在阻塞，必须写明阻塞原因与替代验证
